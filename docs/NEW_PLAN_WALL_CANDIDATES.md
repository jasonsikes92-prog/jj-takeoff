# New-plan wall candidate extraction

The company-scope mapping also drives `/api/company-scope-bids`. New-plan measurement automatically saves its unsent scope additions under `draft_takeoff/company_bid_scopes/` and lists the Markdown files in `summary.json`. Unknown attic HVAC becomes a conditional trade question; it is not silently excluded or assigned a quantity. `company_scope_bids.py --job <draft_takeoff> --output <new-folder>` exports a fresh source-bound revision after edits. Existing folders are preserved. Scope IDs and fingerprints are compatible with the quote comparator, so a changed count invalidates old scope approval. These additions are not complete trade packages and contain no internal costs or markups.

New draft jobs also write `company_scope_review.json`. The estimate server reads this source-bound mapping against the frozen parent intake/profile. The four exterior hose-bibb allowance enters the plumbing water-opening row as a partial EA input, never as the complete plumbing quantity. When `attic_HVAC` is true and the saved practice applies, walkway/platform scope enters framing as a pending quantity. Project overrides retain precedence; unknown facts do not imply inclusion or exclusion. Neither source invents locations, stock quantities or prices. Existing jobs without the mapping remain unchanged. `test_company_scope_review.py` covers source validation, conditional scope, zero/exclusion overrides, duplicate prevention and HTTP export.

`wall_stroke_candidates.py` pairs visible parallel strokes inside an explicitly selected, calibrated view. With an optional `floor_wall_view_review.json`, `new_plan_measure.py` invokes it using styles from reviewed PDF wall-face examples. `wall_view_review.py` validates the plan hash, reviewed floor page, view bounds, reviewer/basis and source edges in both axes. Scale controls and labels are filtered to that view; mixed views or insufficient controls remain unresolved. Without this optional record, the existing filled-strip workflow is unchanged.

Method `native_parallel_wall_strokes_v3` partitions each pair at intervening same-style parallel faces. Partial blockers do not erase unaffected portions; short blockers are not ignored. The prior one-foot overlap cutoff missed jamb returns and produced oversized opening gaps. Version 3 searches overlapping faces down to 2.5 inches and preserves near-square/shorter-than-depth candidates as editable outlines. No missing edge is drawn. This establishes adjacency only, not the structural role of each layer. Summary fields distinguish length/outline candidates, ambiguous pairs, ambiguous intervals, blocked intervals and short unblocked intervals.

`wall_depth_basis.py` reads the job's resolved stud-size assumption from its hashed profile snapshot and project overrides. Supported 2x4/2x6 assumptions provide 3.5/5.5-inch candidate matching with a stated 1/8-inch search tolerance. Every candidate retains the assumption and its provenance without marking it drawing-verified. Mismatched intervals remain in the extraction record, not as scope exclusions. Missing/unsupported sizes leave the unfiltered search intact. Changes during extraction or settings inconsistent with their snapshot/overrides are rejected.

Styles filter the prior broad 91-candidate search but do not certify wall meaning. Unclassified stroke candidates remain explicitly unresolved in wall-run analysis. The preceding broad search and 37-candidate style-filter trial remain recorded in `outputs/burns_wall_stroke_review` and `outputs/burns_wall_view_integration`.

An optional `wall_classification_review.json` in the measurement folder records each stroke candidate as `wall_faces`, `not_wall_faces` or `uncertain`, with reviewer, source interpretation and `source_digest()` from `wall_classification_review.py`. The plan hash must match. Geometry, scale, source-edge or layer-evidence changes invalidate the affected decision; cosmetic edits do not. The separate classification digest accompanies run/gap results. This is an unauthenticated draft interpretation, not human approval or completeness certification.

Both live read-only `/api/wall-runs` and `/api/wall-gap-labels` read the optional review on each request. Only current wall-face decisions enter runs; current nonwall decisions remain listed separately. Uncertain and stale candidates remain unresolved and can still obstruct gaps when their current footprint is usable. Labels are read on accepted run pages; no gap becomes purchased material. The initial extraction snapshots remain unclassified until a review is supplied to the analysis API.

Actual HTTP analysis gives 23 runs, 44 gap candidates and 19 unique tag-location candidates. An actual edit/restore withholds and recovers the changed candidate; wrong-plan reviews are rejected. Original source files, both workbooks and 711 template rows are unchanged. This is not a complete wall takeoff or independent accuracy validation. `tools/new_plan_measure.py` runs `wall_segment_candidates.py` on the uniquely reviewed floor page. It requires usable two-axis dimension calibration and suppresses extraction where printed labels indicate mixed view scales. A title-block scale alone does not enable wall extraction.

`native_filled_wall_rectangles_v1` accepts actual filled rectangles between 2.5 and 6 inches in drawn thickness. The interval is a search envelope, not a wall specification. It verifies four edges rather than trusting a bounding box; white masks, invisible fills and nonrectangular paths are excluded. Exact duplicate geometry preserves all matching CAD path references in one candidate.

Outputs retain the source plan hash, scale controls, PDF page, CAD paths, original bounds and fill color. Length candidates use the rectangle's long-axis centerline. Near-square pieces are area outlines with unresolved direction. Both enter the existing editable measurement store and legend. Candidate IDs depend on source page and bounds. The original source bounds remain evidence when a reviewer edits the measurement points.

`draft_takeoff/wall_segment_candidates.json` records extraction status, limitations and candidates. The summary adds length/short-piece counts and a file link. No candidates are mapped to billable rows and no opening gaps are silently bridged. Filled objects can still be columns, annotations or other nonwall elements; unfilled/compound/diagonal/curved walls are outside this extractor.

Company scope allowances remain distinct from extracted measurements. `plumbing.exterior_hose_bibbs` produces four EA by default even when unmarked, with empty locations and company-default provenance. Project overrides replace the count. `estimate_intake.json` and the measurement summary preserve that allowance; it is not an invented set of plan points.

`wall_run_candidates.py` groups orthogonal length candidates by page, scale and centerline alignment within 0.25 inch. It unions visible intervals and separately reports overlaps, gaps and gross alignment spans. A group can contain disconnected walls; alignment alone does not establish wall continuity or assembly ownership. Short square outlines, diagonal edits and edited polylines remain unresolved. No gap is added to visible material footage, and no stud/plate order or certification is produced.

`draft_takeoff/wall_run_candidates.json` is the initial version-1 snapshot. The measurement editor's read-only `GET /api/wall-runs` derives the current analysis from saved measurement points on every request, returning the measurement version, plan hash and input digest. Use this route after edits rather than treating the initial JSON as current. Original CAD bounds and orientation metadata never replace edited points in this calculation.

`wall_gap_labels.py` extracts four/five-digit numeric tag candidates with optional uppercase suffixes from source text, retaining page, exact text, bounds and orientation. It matches tag centers inside current gaps and within three inches of the alignment. Multiple tags or a tag shared by multiple gaps remain ambiguous. It uses no Roberts-specific coordinate range, source color or opening ID. Numeric syntax is only a candidate filter; opening meaning and size conventions require review.

`wall_gap_label_candidates.json` is the initial tag-association snapshot. `GET /api/wall-gap-labels` recomputes associations from the original PDF and current saved points, with drawing identity checks before and after extraction. A moved boundary can invalidate a prior match; gap IDs must be interpreted with the measurement revision. Tags do not become door/window quantities or manufacturer rough openings automatically.

`wall_short_piece_directions.py` proposes axes for current near-square rectangular outlines when a uniquely oriented tag lies in a clear gap to the nearest aligned peer. Opposing short pieces can support each other; multiple axes, ambiguous peers, intervening pieces, missing tags and edited nonrectangular outlines prevent a proposal. Direction proposals retain the peer, tag and projected-centerline evidence. Source outlines stay editable areas and are never overwritten by this derived calculation.

The tag review includes `short_piece_directions` and a separate `direction_assisted` analysis, with its own run candidates. The latter carries both the original measurement-input digest and the projected-input digest. Its matches remain candidates, with shared tags explicitly flagged. The initial new-plan summary records proposed direction and assisted tag-match counts. A saved edit recalculates both baseline and assisted analyses.

`wall_gap_obstructions.py` screens each gap against other current wall-piece footprints. Orthogonal centerlines retain their drawn thickness; rectangular area pieces retain both actual dimensions. Original bounds never replace edited points. A piece crossing the full alignment centerline range and overlapping the gap interior is recorded as an obstruction; endpoint contact alone is excluded. Nonrectangular/diagonal edits or missing thickness remain listed as unassessed. The footprint digest is separate from the centerline-input digest.

Tag method v3 retains candidate tags on obstructed spans but excludes those spans from unique-opening competition. Baseline and assisted analyses use actual saved footprints, including original short outlines. The prior O12 conflict is resolved because five drawn pieces obstruct the long alternative span. Its true door-sized gap remains uniquely located. This does not certify an opening type, wall assembly or complete site geometry.

Obstruction method v2 separately identifies perpendicular wall-end contacts. Both adjoining host pieces must have compatible current faces, and an accepted perpendicular piece must match the gap width and end at a host face within 0.25 inch. Page, scale, current classification and actual footprint are required; an unclassified/stale stroke cannot supply a junction. A contact without a tag becomes `wall_junction_candidate`; a tag at that contact becomes `junction_tag_conflict`, not a unique opening. No missing interval is added to wall length or stud/plate quantities.

`wall_alignment_breaks.py` reads an optional `wall_alignment_breaks.json` from the measurement folder. Each source-reviewed break binds to the plan, full current alignment/gap and source measurements using `source_binding()`. Only unchanged, untagged gaps can become `separate_wall_runs`; missing or changed gaps retain a stale decision and cannot silently remove an opening. The gap endpoint returns `alignment_review.candidate_sections`, preserving visible intervals and member IDs without adding gap length or purchase quantities. Source edits invalidate the relevant review; baseline and direction-assisted results are assessed separately.

Sections still need assembly roles, heights, header details and material ownership before stock calculation.

`opening_schedule.py` and read-only `/api/opening-schedule` now derive stable opening identities from unique printed tags and current gaps. `opening_schedule_review.json` assigns explicit window/interior/special/exterior/passage roles, locations, room classes and optional window component counts. A review binds to label content/location, source drawing, current alignment/gap and wall evidence. Missing or changed references withhold roles and the enumerated window-unit total; a mull tag never defaults to two units. Four-digit feet/inches nominal sizes are separate from drawn gap widths. Other tag formats remain uninterpreted, and manufacturer rough openings remain unverified.

Door cores, hardware, leaves and product/support details are not approved by an opening role or nominal tag.

`door_policy_revision.py` connects the current schedule to `door_core_specifications()`. A new job uses the door-core rule from its frozen intake/profile when present. An older job lacking that rule remains unresolved unless `door_policy_revision.json` explicitly supplies a hashed snapshot and source explanation. The reader verifies the base intake/profile, same-company revision, file containment and plan identity, then resolves only `doors.interior_core_by_room`. Existing project overrides retain precedence; per-opening `project_core` selections require sources and are withheld with stale opening reviews. Unrelated job settings are never rewritten.
