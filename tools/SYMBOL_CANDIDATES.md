# Editable symbol candidates

`new_plan_measure.py --job <job>` now includes both text-label and raster-template count candidates in the same measurement editor as area candidates. Count groups have individual markers and Add item, Remove item and Done editing controls. They remain pending package references until source, location and coverage review; a count does not establish a contract price or a complete electrical design.

For raster matching, place `electrical_template_definitions.json` in the job. The definition must name the exact plan SHA-256, one-based pages, a legend reference rectangle, an explicit ink choice (`red` or `dark`), search scales and minimum score. Every template needs a label and a source identifying its meaning. Excluded schedule/legend rectangles also need source descriptions. See the Roberts regression definition in `outputs/template_symbol_integration/definitions.json` from the workspace root.

The detector defaults to 72 DPI. Set the top-level `raster_pixels_per_point` to 2 or 3 for smaller symbols (144 or 216 DPI); returned positions and bounding boxes remain in PDF points. Each template can specify `rotations_degrees`, a unique list chosen from 0, 90, 180 and 270, measured counterclockwise in the rendered image; omission searches only 0. The detector searches the supplied scales and orientations and suppresses nearby duplicate matches. It does not select a legend or infer arbitrary angles automatically. Rotated PDF pages still require review. Scores are similarity values, not accuracy probabilities. No matches mean unresolved scope, not zero fixtures. Excessive candidates raise an error instead of silently truncating the result. Dependencies are already recorded in `tools/tests/requirements-golden.txt`.

Results are written to `electrical_template_candidates.json`, including source rectangles, positions, scores and search settings. The new-plan pipeline carries candidate groups into measurements and separate pending references for the template's electrical quote. Purchase quantities and prices remain blank without the required reviews. Changed geometry invalidates the corresponding saved scope approval.

When scaled legend lines are thinner than the plan's device lines, a template may explicitly set `stroke_dilations_pixels` to unique integer radii from 0 through 3 (default `[0]`). Each radius expands the resized reference ink before correlation; it does not move output coordinates or modify the source drawing. The selected radius is retained with every candidate. These are raster pixels at the configured resolution, not construction dimensions. Wider strokes can also create false matches, so this option does not relax source review or establish a certified count.

For symbols whose legend explicitly includes a closed rectangular border, `require_vector_frame: true` adds corroboration from PDF drawing paths. The largest rectangle inside the legend reference establishes its aspect ratio. A candidate must contain a unique centered rectangle with a matching ratio; each accepted frame retains its PDF path sequence numbers. Unsupported/open borders and ambiguous nested frames are rejected. A missing vector legend frame raises an error, so this option cannot silently certify scanned drawings. Rejected raster matches remain in `uncorroborated_candidates` for inspection. The frame test establishes symbol geometry, not electrical product type or circuit design; nearby labels and leaders still need scope review.

The September 17 Roberts regression found six fan symbols; all six were visually checked against the drawing. The regression reused prior sheet review and is not an unseen-plan accuracy test. Other electrical classes, varied drawing quality and independent held-out homes remain unproven.

For vector PDFs, `electrical_vector_definitions.json` enables a separate circle-and-parallel-bar method. It requires the plan hash, page/ink/exclusions and explicitly identified legend bounds with diameter-scale ranges. The source circles, paired bars and optional center lines establish candidate shape classes. `qualifying_labels` use the same source-described text definitions as text candidates; nearby special labels and tight enclosing rectangles withhold those shapes from ordinary groups. Ambiguous labels or multiple matching legends stay recorded rather than being silently assigned. See `outputs/electrical_vector_device_review/definitions.json` from the workspace root for a source-bound example.

The new-plan pipeline writes `electrical_vector_candidates.json` and adds these groups to the editor's pending electrical references. Qualified shapes retain their evidence for separate scope ownership and are not emitted again in the ordinary count. This method handles the supported cubic-circle and line geometry; it does not certify scanned symbols, arbitrary alternative symbols, missing labels, redline interpretation or circuit requirements. Configured legend meaning still needs review, and an equipment annotation can override an apparent generic device symbol.

`electrical_stroke_definitions.json` handles supported polyline symbols with one distinct longest anchor stroke, including tightly grouped switches. Each source-bound page defines one legend (`id`, `label`, `meaning_source`, `bbox_pt`, `ink`, positive `scale_range`, and `maximum_error_ratio` no greater than 0.05). The method aligns the reference to candidate anchors at their drawn scale and rotation, and checks distances from sampled reference strokes to actual PDF line segments. It preserves anchor/support path numbers. Extra surrounding strokes do not automatically reject a candidate, so visual and semantic review still matters. Scans or missing/ambiguous vector anchors require another method.

Optional `qualifying_labels` withhold the uniquely nearest symbol within one anchor length. Near ties and competing label claims stay unresolved. Qualified shapes remain in the evidence and do not enter the unqualified count, avoiding duplicate three-way switch references. `electrical_stroke_candidates.json` and the pending electrical editor group retain these limits. The source-bound Roberts example is `outputs/electrical_switch_review/stroke_definitions.json`; its 24 single-pole and 12 qualified three-way symbols were visually checked, but this remains a development-exposed regression.
